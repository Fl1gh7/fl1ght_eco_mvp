# Как тестировать ServiceFl1ght

Ключи уже лежат в корне в `.env` — отдельно ничего собирать не нужно. Все команды — **из корня проекта**, с включённым venv.

```bash
cd /путь/к/ServiceFl1ght
source venv/bin/activate          # Windows: venv\Scripts\activate
```

Если YandexGPT не отвечает, в `.env` пустые `YANDEX_API_KEY` / `YANDEX_FOLDER_ID`. Остальное (VK, Telegram, Redis) нужно только для шагов 4–5.

---

## 1. Быстрая проверка без ИИ (30 секунд)

Не ходит в интернет, не тратит токены:

```bash
python -m unittest tests.test_db_manager tests.test_matcher tests.test_webhook_auth
```

Должно быть `OK`. Это база, матчер прайса и проверка секретов вебхуков.

---

## 2. Полный конвейер — главный скрипт

```bash
python test_full_logic.py
```

Это Сито + прайс + Продавец + запись в `database.db`. Пишете как клиент, в консоли видно каждый слой.

Выход: `выход` или Ctrl+C.

### Сначала спам (Сито должно отсечь)

```
купить продвижение в директ
```

Ожидание: `Отклонено`, статус trash, до Продавца дело не дошло.

### Потом живой заказ (скопируйте по одному сообщению)

```
Сломался экран на айфоне 13, сколько стоит замена?
```

Дальше отвечайте по смыслу, но закройте все 6 пунктов:

- модель (уже есть: iPhone 13)
- поломка (экран)
- цена — явно согласитесь с суммой или выберите оригинал/копию
- адрес: `Тестовая улица, дом 1`
- время **интервалом**: `завтра с 14:00 до 16:00` (не «в 15:00»)
- телефон: `+7 999 000-00-01`

Ожидание:

- после первого сообщения — `Целевой запрос`, подбор цен из прайса, ответ Продавца;
- пока чего-то не хватает — статус `ACTIVE`;
- когда всё собрано — `SUCCESS` и «Диалог завершен».

Проверка «дорого»:

```
дорого, я подумаю, напишу позже
```

Ожидание: статус `DELAYED`, не SUCCESS.

Цена должна быть похожа на прайс (экран 13, не Pro Max), не случайная цифра.

---

## 3. Только Продавец (без Сита)

Если шаг 2 уже ок, это необязательно:

```bash
python seller_chat/test_closer.py
```

Сразу диалог с менеджером и прайсом, без отсева спама. Тот же сценарий с 6 полями. Выход: `выход`.

---

## 4. Скаут VK на бою

Нужны живые Redis и Celery worker (иначе задача повиснет в очереди).

```bash
python run_scout_now.py
```

Скрипт кладёт обход пабликов в очередь. Через пару минут:

1. Откройте админку: `https://<хост>/crm` (логин/пароль — `CRM_ADMIN_USER` / `CRM_ADMIN_PASS` из `.env`).
2. Должны появиться новые строки в логах (VK, score, лид или мусор).

Если Task ID напечатался, а в админке пусто — не запущен worker:

```bash
celery -A core.celery_app worker --loglevel=info
```

Beat сам гоняет скаута раз в 2 часа, `run_scout_now.py` — ручной пинок.

Кнопки «Ищейка TG/VK» в админке **не нажимайте** без нужды: TG-ищейка останавливает радар и лезет в чаты, VK-ищейка **перезаписывает** список пабликов.

---

## 5. Живые каналы (если уже подняты)

`.env` уже содержит токены. Проверяйте руками как клиент:

| Куда | Что сделать | Успех |
|---|---|---|
| Чат на сайте или `POST /api/chat` | Тот же сценарий, что в шаге 2 | Ответы ИИ, в конце заказ |
| Официальный Telegram-бот | Написать в **личку** боту | То же самое. После SUCCESS — сообщение в канал алертов (`TELEGRAM_CHAT_ID`) |
| ЛС сообщества VK | Написать в ЛС **группы** | То же. Первое спам-сообщение Сито может оборвать |
| Avito | Ничего не делать | Канал-заглушка. Вебхук всегда **501** — так и задумано |

В Telegram-боте Сита нет: даже странное первое сообщение уйдёт Продавцу.

Админка `/crm` — логи скаутов. Список заказов:

в браузере откроется окно логина (те же CRM_* из `.env`):

`https://<хост>/api/crm/orders`

## Если сломалось

| Симптом | Куда смотреть |
|---|---|
| `Ключи Yandex не найдены` | `.env` в корне, запускаете не из корня проекта |
| unittest падает | `python core/database.py` и при необходимости `python import_excel.py` |
| `test_full_logic` молчит / ошибка ИИ | ключи Yandex, интернет |
| Скаут «отправил задачу», логов нет | Redis + `celery worker` |
| Бот в VK/TG молчит | на сервере заданы `VK_CALLBACK_SECRET` и `TELEGRAM_WEBHOOK_SECRET`, вебхуки перевыставлены |
| Avito 501 | не баг |
